2. REGRA FUNDAMENTAL — NÃO CONECTAR O SUPABASE NESTA PRIMEIRA FASE

O projeto utilizará Supabase futuramente, mas NÃO queremos realizar a
integração agora.

Nesta primeira fase: - Não conectar o Supabase. - Não executar operações
de leitura ou escrita no banco de dados. - Não criar tabelas. - Não
alterar tabelas. - Não executar migrações. - Não modificar estruturas
existentes. - Não solicitar credenciais ou chaves de conexão. - Não
modificar políticas RLS. - Não conectar autenticação ou armazenamento do
Supabase.

O que deverá ser feito agora?

Desenvolver toda a estrutura do FerveC Gastronomia utilizando uma
arquitetura independente do banco de dados.

Criar uma camada provisória de armazenamento de dados, separada da
lógica das funcionalidades. Essa camada poderá utilizar armazenamento
local, dados temporários ou dados de demonstração, conforme a
necessidade de cada recurso.

Arquitetura preparada para o futuro

Organizar o projeto para que, posteriormente, possamos conectar o
Supabase sem precisar reconstruir o site.

Para isso: - Separar a lógica de negócio da camada de armazenamento. -
Criar interfaces de acesso aos dados. - Centralizar operações de
cadastro, consulta, atualização e exclusão. - Evitar chamadas diretas ao
banco espalhadas pelos componentes. - Documentar quais estruturas
precisarão ser conectadas futuramente. - Manter os identificadores e
relacionamentos necessários para a futura integração. - Permitir
substituir a camada provisória pela integração definitiva.

IMPORTANTE: Não confundir preparação arquitetural com integração real.
Nesta fase, o Supabase deverá permanecer completamente desconectado.

Identificação dos dados provisórios

Toda funcionalidade que utilizar dados temporários deverá ser
identificada como provisória.

Não apresentar cadastros, pagamentos, compras, cupons ou progressos
simulados como se fossem registros definitivos.

Não prometer sincronização entre dispositivos nesta fase.

4. MEU PROGRESSO — INTEGRAÇÃO COM TODOS OS CURSOS

A área Meu Progresso deverá funcionar como um painel central de
acompanhamento da evolução do aluno.

Porcentagem de conclusão

Calcular automaticamente a porcentagem utilizando os dados reais das
atividades concluídas na camada provisória.

Não utilizar porcentagens fixas, decorativas ou baseadas somente no
módulo selecionado.

Módulos

No curso Chef Cremonese Massas Italianas, existem seis módulos.

O sistema deverá apresentar: - Módulos disponíveis. - Módulos em
andamento. - Módulos concluídos. - Módulos bloqueados.

Os cadeados deverão atualizar conforme o aluno cumprir os requisitos de
cada módulo.

Integração das etapas

Integrar corretamente: - AULA. - TRABALHO. - REVISÃO. - PROVA. -
CERTIFICADO.

Cada etapa deverá atualizar o progresso geral e o progresso individual
do módulo.

Certificado

Quando o aluno cumprir os requisitos e for aprovado, o certificado
deverá ser liberado conforme as regras do curso.

Ao clicar no certificado dentro de Meu Progresso, direcionar diretamente
para a aba CERTIFICADO.

Compatibilidade com novos cursos

Não desenvolver essa lógica exclusivamente para Massas Italianas.

Criar uma estrutura reutilizável para que novos cursos, módulos e etapas
sejam reconhecidos automaticamente, respeitando os requisitos próprios
de cada curso.

Persistência provisória

Utilizar armazenamento local quando apropriado, permitindo testar a
navegação e o progresso durante o desenvolvimento.

Deixar explícito que a persistência definitiva na nuvem será
implementada somente na segunda fase.

6. GERENCIAMENTO DE CUPONS DE DESCONTO

Criar uma funcionalidade importante dentro do painel administrativo
chamada GERENCIAR CUPONS.

Essa funcionalidade deverá ter destaque entre as ferramentas
administrativas, sem ocupar espaço excessivo.

Gerador de cupons

O administrador deverá conseguir: 1. Clicar em Gerar novo cupom. 2.
Gerar automaticamente um código exclusivo de seis dígitos. 3. Escolher o
percentual de desconto. 4. Definir a validade. 5. Definir a quantidade
de utilizações permitidas. 6. Salvar o cupom na camada provisória. 7.
Copiar o código para compartilhar.

Percentuais disponíveis

10%, 20%, 30%, 40%, 50%, 60%, 70%, 80%, 90% e 100%.

O percentual deverá ser associado ao código gerado.

Exemplo: - Código: 091100. - Desconto: 90%.

O código deverá aplicar o percentual correspondente sobre o valor do
produto adquirido.

Cupom de 100%

Quando o administrador selecionar 100%, o curso deverá ficar totalmente
gratuito no fluxo demonstrativo.

O sistema deverá registrar a utilização demonstrativa e a aquisição
provisória, respeitando as regras de identificação do aluno.

Não deverá exigir pagamento de valor zero por meio de gateway.

Validade

Validade padrão: 7 dias a partir da criação.

Permitir ao administrador escolher outros prazos: - 1 dia. - 3 dias. - 7
dias. - 15 dias. - 30 dias.

Controle administrativo

Permitir: - Consultar cupons. - Consultar percentuais. - Consultar
validade. - Consultar quantidade de utilizações. - Consultar utilizações
demonstrativas. - Consultar em qual pedido demonstrativo foi
utilizado. - Desativar cupons. - Identificar cupons expirados. -
Identificar cupons utilizados.

Os códigos deverão ser únicos.

Implementar as regras de validação na camada de negócio, deixando a
validação definitiva no servidor para a futura integração.

Identificar claramente que os dados ainda são provisórios. Não
apresentar a validação local como proteção antifraude ou validação
segura em servidor.
